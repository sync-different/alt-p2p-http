First release. alt-p2p-http tunnels a localhost HTTP port between two machines —
peer to peer, encrypted, no public URL. One side runs `serve` next to an HTTP server;
the other runs `connect` and gets it on a local port. Traffic flows directly between
the two machines over an encrypted P2P link (UDP hole punching + DTLS), with an
automatic TCP-relay fallback when networks are strict — still end-to-end encrypted;
the relay never sees plaintext.

Built on [alt-p2p](https://github.com/sync-different/alt-p2p). Deliberately not an
ngrok clone: both ends share a session name and key. You're sharing a port with a
peer, not publishing it to the internet.

## Install

Download `alt-p2p-http-0.1.0.jar` below. Needs Java 17+. That's it.

## Usage

```bash
# Machine A — has an HTTP server on localhost:3000 (a dev server, Ollama, anything)
java -jar alt-p2p-http-0.1.0.jar serve --port 3000 \
    -s mysession --psk mysecret --server <coord-host>:9000 --allow-relay

# Machine B
java -jar alt-p2p-http-0.1.0.jar connect --local-port 8080 \
    -s mysession --psk mysecret --server <coord-host>:9000 --allow-relay
# open http://127.0.0.1:8080/
```

The coordination server both peers point at is the self-hostable alt-p2p server:
`java -jar alt-p2p.jar server --psk <key>`.

## Validated

- HTTP GET/POST byte-for-byte (2 MB bodies SHA-256-compared), chunked encoding,
  multipart uploads, 404/status pass-through, keep-alive, 8-way concurrent requests.
- WebSockets (RFC 6455 handshake + echo through the tunnel).
- Progressive streaming: SSE chunks arrive live, not buffered — remote LLM token
  streams (Ollama, llama.cpp, LocalAI) feel local.
- HTTPS passes through untouched (TLS terminates at the far server — a self-signed
  cert warns in the browser exactly as it would locally).
- Both carriers: direct hole-punched UDP and the TCP relay fallback.

## Limits (honest list)

- One client at a time per session; the next client can connect as soon as the
  previous one leaves. Run multiple `serve` processes on different sessions to share
  with several people at once.
- `connect` exits when the peer drops (non-zero) — rerun it or wrap it in a
  supervisor to reconnect.
- No Windows/macOS/Linux packaging — it's one JAR, bring Java 17+.

AGPL-3.0, like its siblings [alt-p2p-lore](https://github.com/sync-different/alt-p2p-lore)
and [alt-p2p-bbs](https://github.com/sync-different/alt-p2p-bbs).
